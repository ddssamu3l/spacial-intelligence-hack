# Memo 1: lifted 2-D foundation features in 3-D maps
- Lifting recipe: per-pixel pinhole projection + depth occlusion test + MEAN pooling across views (OpenScene, Lexicon3D, VLMaps). OpenScene fusion ablation: random view 38.2 / median 40.1 / mean 41.4 mIoU -> averaging is a small win. ConceptFusion weights by radial distance from image centre (alpha=exp(-gamma^2/2sigma^2), sigma 0.6); no incidence-angle weighting anywhere. LERF: discard points seen by <5 views; DINO as regulariser.
- Nobody stores full-dim per primitive: FiT3D D=32 -> 67.15, D=64 -> 67.50 mIoU, 128 infeasible; SERF: DINOv3 1280-d -> 64-d latent per 0.02 m point, MLP decoder back, K=6 NN; SceneDINO 64 -> 768. Three votes for 64-d LEARNED compression. No PCA-64 retention number exists (UNVERIFIED).
- What patch features encode: geometry strongly (Probe3D DINOv2-L depth d1 94.84, normals 64.05%; CLIP worst 52.11); object/part strongly (ADE20k linear 47.3 vs OpenCLIP 39.3); F3RM: DINO struggles with similar-looking distractors. Material: only CLIP-aligned evidence. Room/scene context WEAK and CLS-only: Places205 DINOv2-L 67.3 vs OpenCLIP 69.8; SUN397 78.7 vs 84.0; DINOv3 7B 70.0. No patch-level room-type probe exists.
- Layer: Probe3D correspondence peaks at Block1 (early), not last; DINOv2 depth heads concat layers {3,6,9,12}.
- Instance matching: DINO's strongest suit. Oxford-H mAP DINOv2-L 54.0 vs OpenCLIP 19.7; DINOv3 7B 60.7. Patch-level same-instance NAVI recall DINOv3 64.4, DINOv2-g 60.1, SigLIP2 49.4. CATCH: viewpoint collapse ~5x: ScanNet recall 56.1 (<15 deg) -> 10.3 (60-180 deg). "View-consistent, not 3-D consistent."
- Photo-query precedents: ConceptFusion image-query 3D mIoU 0.331; AnyImageNav [2604.05351]: cosine between DINOv2 patch features of goal photo and current view projected to BEV to steer frontiers: 93.1% SR Gibson image-goal, 82.6% HM3D instance-image-goal (SOTA).
- Lexicon3D lifted-to-points linear probe ScanNet mIoU: DINOv2 62.8 > LSeg 47.5 > SD 42.6 > ... > CLIP 3.4. DINOv2 25 ms / 1.19 GB on A100. CLIP catastrophic for dense 3-D.
- Cubemap vs ERP: OPEN. PanDA (depth, DINOv2 backbones): ERP AbsRel 0.1654 beats cubemap 0.2238 at matched angular res. MonoDream Tab 8 (R2R-CE nav, controlled): cubemap SR 39.6/SPL 35.3 vs ERP 38.5/33.2. Pinhole segmenters lose ~50% mIoU on ERP unadapted. Keep ERP gravity-aligned. No cross-projection benchmark. Embodied-AI convention: perspective sub-views (Fried: 36 = 12 headings x 3 elevations).
- View consistency (SceneDINO, RAFT-warped): DINOv2 cos 0.70; FiT3D 0.82 (but L1 worse: 15.83 -> 22.86 -> compare by cosine, don't average raw); SceneDINO 0.96. FiT3D: one epoch of 3-D-aware fine-tuning helps, more hurts.
- Constants: DINOv2 patch 14, S 384/B 768/L 1024; 518^2 -> 1369 tokens. DINOv3 patch 16; GFLOPs @512: S 63, S+ 79, B 216, L 721. ERP 512x1024 = 2628 tokens vs 6x518^2 cubemap = 8214. Jetson: six 512^2 faces = 0.38 TFLOP ViT-S. Never put SAM-style mask proposals in loop (10-15 s/image).
- Design: lift per patch, average across views with radial weight + >=5-view filter, keep per-cell feature spread as uncertainty; 64-d learned compressor not PCA; teddy match well-supported but viewpoint is the risk -> weak relevance field, not hard detector; room context must be ASSEMBLED by the transformer from many tokens + position; projection = measured arm; FiT3D-style one-epoch pass as insurance.
